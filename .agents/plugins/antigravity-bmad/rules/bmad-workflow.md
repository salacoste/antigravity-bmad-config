# BMad routing & runtime protection

- When the user references BMad roles, phases, or artifacts (PRD,
  architecture, epics, stories, QA), invoke the matching installed skill
  (`bmad-agent-analyst|pm|ux-designer|architect|dev`, `bmad-prd`,
  `bmad-architecture`, `bmad-build`, `bmad-code-review`, …) instead of
  improvising an equivalent persona or document.
- Multi-option decisions during BMad work → use the `ask_question` tool
  with concrete options rather than open-ended prose.
- Never edit files under `_bmad/` except `_bmad/custom/`. The rest is
  installer-managed (regenerated by `./setup.sh` from the pinned version
  in `.bmad-version`).
- BMad artifacts live under `_bmad-output/` (paths resolved from BMAD
  config, not hardcoded). Don't scatter planning docs elsewhere.
- Unsure which skill fits → invoke `bmad-help`; for whole-loop sequencing
  use `bmad-orchestrate`.
